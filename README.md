# 科研困难与贡献分析（GitHub Pages 版）

纯静态网页，无须安装 Node.js；可以放到 GitHub Pages 或下载后用浏览器打开。仅需将一段困难或贡献文字粘贴到首页，点击「AI 识别并评审」，模型自动判断是困难、贡献还是两者，并提取问题、方法、困难、效果，解释对应关系。

## 使用方法

1. 在「粘贴困难或贡献」输入一段中文或英文的原始文字。**不必拆分或填满四项，也不要求有标题。**
2. 「评审范围」默认自动识别；如果模型误判，可以强制选择「只评困难」「只评贡献」或「困难与贡献一起评」。
3. 在「模型设置」输入自己的供应商、API 地址、模型及密钥，然后点击「AI 识别并评审」。
4. 评审先显示**从原文识别的结构与证据**，再显示角色区别、六条关系、重点问题和修改建议。原文没写到的项目应显示「未明确表达」，不能由模型编造。
5. 「结构化填写（高级模式）」是可选功能：当原始文字输入框为空时，才使用高级表单；没有四项全部填满也可以请求 AI 评审。
6. 如果浏览器直接调用 API 遇到跨域 CORS 限制，可点击「复制评审提问」，将其粘贴到已有的模型对话页面进行评审。此操作无须配置 API Key。

题目设置也是可选的：可以随机出题、手动指定或完全不填。填写内容和供应商设置保存在当前浏览器，刷新后可恢复。

## GitHub Pages 部署

1. 在 GitHub 创建公开或允许 Pages 的仓库。
2. 将压缩包内的 `index.html`、`.nojekyll` 上传到仓库**根目录**（不要只上传 ZIP）。
3. 在仓库 `Settings → Pages → Build and deployment` 选择 `Deploy from a branch`、`main` 和 `/(root)`，保存。
4. 等待部署后访问 GitHub Pages 提供的网址。

参考：https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 隐私与限制

- 该项目是静态网站，AI 请求直接从使用者浏览器访问模型供应商。**是否能调用取决于供应商跨域 CORS 策略**；本项目不能替供应商解除跨域限制。
- **绝对不要将任何 API Key 写入 GitHub 仓库。** 用户在网页中自行输入密钥；GitHub Pages 环境下默认不长期储存密钥。勾选“记住 API Key”后会以明文保存在浏览器 localStorage，不建议在共享设备上使用。
- 网页草稿保存在本地浏览器 localStorage，不会上传到 GitHub；但点击「AI 识别并评审」会向用户填写的供应商发送评审文字和密钥，注意论文保密要求。
- 从自由文字识别结构需要模型 API 真实返回；本地的「结构自检」仅提供人工检查问题，不会假称自己完成语义理解。
- AI 的论证分析不能取代严格证明或已有文献的新颖性检索。
